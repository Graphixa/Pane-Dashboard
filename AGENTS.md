# Working on Pane

Read [SPEC.md](SPEC.md) before changing behaviour and [DESIGN.md](DESIGN.md) before any UI work. All interactive UI must go through the shared entry point in `web/src/design/components.tsx`; those primitives use Radix UI where an interaction primitive exists. Screens must not render raw interactive controls or add a second component library. Add reference examples for new components or variants. Pane is a single-user self-hosted launcher, not a general-purpose canvas or Docker manager.

- Keep the Go server small and the React state explicit. No database or second layout engine.
- React Grid Layout owns outer dragging, resizing and collision handling. CSS Grid owns app slots.
- Schema 2 stores x/y in 8 px units and w/h in app columns/rows. New placement and movement snap to 16 px; preserve existing coordinates until moved. Convert to library frame dimensions at the boundary only.
- Keep fixed 80 px icons, immediate 4 × 1 pane creation, attached external titles and 16 px gutters. Reserve title space in both modes. Centre the dotted move grip above the pane, keep resize marks perpendicular and offset, and fill the remaining viewport with the edit grid.
- Keep the header name/logo configurable, without promotional headings, counts or footer copy. Bundle Geist, Rubik and Oxanium locally (Geist default); title size defaults to 18 px, with a global 14–22 px setting. Missing app URLs must not dim artwork.
- Settings navigation is General, Appearance, Background, Panes, Import & backup, About. Keep page title, icon and custom logo in General → Branding, header-button and app-tile labels in General → Labels, workspace width in General → Workspace, theme/colours/typography in Appearance, backgrounds on Background, and global pane finish in Panes. Preserve drafts across sections and validate all fields on Apply. Settings page titles stay in the DOM for accessibility but are visually hidden; the sidebar marks the current page. Appearance uses typographic section headings, not nested tabs. Settings rows share stable label/control columns; Range is always stacked (label and value above a full-width track) in Fine tuning, Readability, and Background adjust sheets. Settings help uses `HelpTip` (circled `?` beside the section or control label); do not add under-label or under-heading help subtitles—keep visible `Section` description only for content such as About version. Background: compact Current band (image or live still with the same still-first hover/focus preview as chooser tiles, meaningful media name, Change wallpaper; Position/Playback for image/video), Enhancements (Tint switch with Customise under the label — disabled when off; Screen Effects select with Customise; Add Motion select always shown last, greyed with hover tip for non-photo/live/video wallpapers; Motion/Effect/Tint detail sheets use Modal `footer` for a three-region layout — fixed title/Close, scrollable body, fixed Done — sized to content up to about `min(70dvh, 640px)` with compact SettingsGroup density), then Readability (Theme overlay). Change wallpaper is a bottom-docked Browse → category-grid chooser (Colours, optional Recently selected, category cards for My media / Gradients / bundled folders; one Add media control; Recently selected holds only image/video selections, updates immediately in the Settings-owned draft, and excludes colours/gradients/None; chooser discard restores its history snapshot; Settings Cancel discards history and Apply persists the whole history only after a matching successful save; Use wallpaper confirms draft only; dirty dismiss confirms before restoring the pre-chooser snapshot; no load-time autoplay tiles — live thumbs use catalogue or durable asset `/poster` stills (My media videos capture on Add media; hover backfills when missing); play muted after hover linger (~180 ms) or keyboard focus only, shared with Current/Recently selected; border plus checkmark on selected tiles; static before live in category grids; names from media meta or catalogue titles). Colours `solid` paints a fixed tint over theme `--bg`, not an opaque fill; None lives in the Colours row. My media stays newest-first; selecting a library tile must not reorder. Bundled categories come from build-time `wallpapers/` → `builtin/` catalogue (`npm run catalogue`). Effects are transparent packs in `web/src/effects/` (snow / fireflies / shooting-stars)—no Dynamic wallpaper shelf or arbitrary CSS upload. Remove miniature settings previews. Preview draft dashboard/appearance live on the shell and Settings dialog without autosave; Cancel restores the prior applied look. Settings opens without a dimmed lightbox so dashboard colours stay true; the dialog uses a soft drop shadow for elevation. Preview-adjust sheets still hide Settings chrome. Keep sidebar icons and labels in fixed, left-aligned tracks.
- Appearance is global only: never introduce per-pane colours, glass or theme overrides. Header brand is independent show/hide for icon and page title, plus optional wide custom logo that replaces the title; keep the accessible name from the title string.
- Uploaded images and videos are bounded media files beside the configuration (`media/`), referenced from schema 4 config (not embedded data URIs). Stage/commit through `/api/media/*`; Apply uses the ordinary revision-protected save. Never accept SVG/HTML uploads, GIF, animated WebP, arbitrary CSS or server-side fetching of user media URLs. Portable backups are archives that include referenced local media.
- Keep backgrounds decorative, respect reduced motion/transparency, and preserve solid-surface fallbacks. Composition is wallpaper → optional creative tint → optional transparent effect (snow/fireflies/shooting-stars) → theme overlay. Video loops are the animated wallpaper path; full CSS/HTML dynamic scenes are retired. See [docs/background-media-contracts.md](docs/background-media-contracts.md). Global glass may use a layered liquid-glass surface (empty warp with backdrop blur and gated per-pane SVG edge refraction sized to each pane, unfiltered tint, soft shine/rim); never filter tint or content. Expose opacity/blur/saturation/displacement/aberration under Panes fine tuning. Automatically degrade refraction for unsupported browsers, reduced motion/transparency, offscreen panes, edit drag/resize and many visible panes. Validate palette contrast on both client and server. Do not claim the glass finish is physical refraction.
- Schema 4 is the runtime configuration: shared app definitions, named Spaces with per-space pane layouts, and global appearance. Explicit schema 3 → 4 conversion at load/import backs up original bytes and wraps the prior dashboard as one Home space. Schema 1/2 remain rejected without rewrite. Missing config still creates defaults. Never silently truncate apps or overwrite an invalid configuration. Spaces are explored on `feature/spaces`; see [docs/spaces-implementation-plan.md](docs/spaces-implementation-plan.md).
- Never compact layouts, push neighbours, swap occupied app slots, or persist mobile presentation coordinates.
- Read mode must not expose dashboard mutation controls. Edit mode is transient UI state, not authorisation.
- Preserve intentional gaps and reject geometry that clips an occupied app slot.
- Validate all configuration on both sides. Save atomically and preserve the previous file on failure.
- Docker discovery is opt-in and read-only. Never add Docker management endpoints or expose daemon responses wholesale.
- Keep URL handling restricted to HTTP(S). Do not render imported HTML.
- Use Australian English. Keep accessible names when button labels are hidden.
- Update tests and SPEC.md when behaviour changes. Run `npm ci && npm test && npm run build` in web, copy `web/dist` to `internal/ui/dist`, then `go test ./... && go vet ./...` at the root (`go run ./cmd/pane`). See [docs/repo-layout.md](docs/repo-layout.md).
- Keep Docker socket access warnings prominent. Do not claim a read-only socket mount makes the Docker API read-only.
- Do not commit runtime configuration, credentials, node_modules, generated binaries or private service URLs.
