# Working on Pane

Read [SPEC.md](SPEC.md) before changing behaviour and [DESIGN.md](DESIGN.md) before any UI work. All interactive UI must go through the shared entry point in `web/src/design/components.tsx`; those primitives use Radix UI where an interaction primitive exists. Screens must not render raw interactive controls or add a second component library. Add reference examples for new components or variants. Pane is a single-user self-hosted launcher, not a general-purpose canvas or Docker manager.

- Keep the Go server small and the React state explicit. No database or second layout engine.
- React Grid Layout owns outer dragging, resizing and collision handling. CSS Grid owns app slots.
- Schema 2 stores x/y in 8 px units and w/h in app columns/rows. New placement and movement snap to 16 px; preserve existing coordinates until moved. Convert to library frame dimensions at the boundary only.
- Keep fixed 80 px icons, immediate 4 × 1 pane creation, attached external titles and 16 px gutters. Reserve title space in both modes. Centre the dotted move grip above the pane, keep resize marks perpendicular and offset, and fill the remaining viewport with the edit grid.
- Keep the header name/logo configurable, without promotional headings, counts or footer copy. Bundle Geist, Rubik and Oxanium locally (Geist default); title size defaults to 18 px, with a global 14–22 px setting. Missing app URLs must not dim artwork.
- Settings navigation is General, Appearance, Background, Panes, Import & backup, About. Keep logo/name in General, theme/colours/typography in Appearance, backgrounds on Background, and global finish plus app-label visibility in Panes. Preserve drafts across sections and validate all fields on Apply. Appearance uses typographic section headings, not nested tabs. Background uses a compact Current band (preview, Currently set, Change wallpaper) with Image position as a Settings row when needed, Motion effects (image only) / Wallpaper overlay / Dynamic Customize with per-effect sheets below; Change wallpaper opens a bottom-docked, non-lightbox Choose wallpaper sheet with vertically scrollable shelves (Colours with custom + then accent chips; My images / Gradients / Dynamic tiles sit in an inset settings group and clip on the card edge only while others are offscreen; the first tile stays inset at the start and the last stays inset at the end of the scroll. The sheet body uses the themed vertical ScrollArea, spaced clear of those boxes (no chevrons or strip scrollbars)). The sheet is short enough that Colours and My images stay fully in view and about half of Gradients is visible; Show all uses that same height and opens a three-column grid—not Settings nested page tabs. Title-bar Close exits to Settings; inside Show all, footer Back returns to shelves and Select confirms back to Settings; colour/tile selection previews the draft without closing the sheet. Colours `solid` paints a fixed tint over theme `--bg`, not an opaque fill. My images stay newest-first; selecting a library tile must not reorder. Choose wallpaper / Motion / Overlay / Dynamic Customize remain bottom non-lightbox preview-adjust sheets that hide Settings chrome. Dynamic wallpapers are bundled packs in `web/dynamic/` (CSS + optional thin HTML, no pack JS); registry drives the Dynamic shelf and schema controls—no arbitrary CSS upload or community import in this phase. Remove miniature settings previews. Preview draft dashboard/appearance live on the shell and Settings dialog without autosave; Cancel restores the prior applied look. Keep the Settings backdrop dimmed without blur except during Choose wallpaper / Motion / Overlay / Dynamic preview-adjust. Keep sidebar icons and labels in fixed, left-aligned tracks.
- Appearance is global only: never introduce per-pane colours, glass or theme overrides. Brand mode is either a square icon plus name or a wide logo; keep the accessible name in both modes.
- Uploaded images and videos are bounded media files beside the configuration (`media/`), referenced from schema 3 config (not embedded data URIs). Stage/commit through `/api/media/*`; Apply uses the ordinary revision-protected save. Never accept SVG/HTML uploads, GIF, animated WebP, arbitrary CSS or server-side fetching of user media URLs. Portable backups are archives that include referenced local media.
- Keep backgrounds decorative, respect reduced motion/transparency, and preserve solid-surface fallbacks. Composition is wallpaper → optional creative tint → optional transparent effect (snow/fireflies/shooting-stars) → theme overlay. Video loops are the animated wallpaper path; full CSS/HTML dynamic scenes are retired. See [docs/background-media-contracts.md](docs/background-media-contracts.md). Global glass may use a layered liquid-glass surface (empty warp with backdrop blur and gated per-pane SVG edge refraction sized to each pane, unfiltered tint, soft shine/rim); never filter tint or content. Expose opacity/blur/saturation/displacement/aberration under Panes fine tuning. Automatically degrade refraction for unsupported browsers, reduced motion/transparency, offscreen panes, edit drag/resize and many visible panes. Validate palette contrast on both client and server. Do not claim the glass finish is physical refraction.
- Schema 3 is a breaking rewrite for this unreleased prototype (Path A): do not migrate older `pane.yaml` backgrounds. Invalid or unsupported versions fail clearly without rewriting the file; missing config still creates defaults. Never silently truncate apps or overwrite an invalid configuration.
- Never compact layouts, push neighbours, swap occupied app slots, or persist mobile presentation coordinates.
- Read mode must not expose dashboard mutation controls. Edit mode is transient UI state, not authorisation.
- Preserve intentional gaps and reject geometry that clips an occupied app slot.
- Validate all configuration on both sides. Save atomically and preserve the previous file on failure.
- Docker discovery is opt-in and read-only. Never add Docker management endpoints or expose daemon responses wholesale.
- Keep URL handling restricted to HTTP(S). Do not render imported HTML.
- Use Australian English. Keep accessible names when button labels are hidden.
- Update tests and SPEC.md when behaviour changes. Run `npm ci && npm test && npm run build` in web, then `go test ./... && go vet ./...` at the root.
- Keep Docker socket access warnings prominent. Do not claim a read-only socket mount makes the Docker API read-only.
- Do not commit runtime configuration, credentials, node_modules, generated binaries or private service URLs.
